# 本机信息（System Info）

随应用发布的内置扩展，源码在 `factory/extensions/system-info/`。让模型和用户查看**这台电脑**
的真实情况，而不是靠猜：CPU、内存、硬盘空间、网络连接、对外开放的接口。

**只读。** 它不修改任何东西：不关端口、不结束进程、不写文件。工具权限分组是 `read`。

## 怎么用

1. 在输入框的 **Extension ▾** 菜单里选 **本机信息**（英文 *System Info*，繁体 *本機資訊*）。
2. 左下角出现高亮标签和两个按钮，**点按钮会直接让助手回答**，不弹窗：
   - **概览**：CPU、内存、硬盘、网络的概况，指出偏紧的地方；
   - **对外端口**：哪些端口对网络开放，按进程归类，说明哪些只限本机。
3. 也可以直接提问，例如“C 盘还剩多少空间？”“谁在监听 8080？”。模型会调用 `system_info`
   工具，按结果回答。
4. 这个工具本身是**应用级**的：不在扩展模式下，模型也能调用它。选中扩展模式时，应用多给模型一段
   说明（`prompts/active.md`），告诉它遇到本机问题要先查工具、不要凭印象回答。

## `system_info` 工具

参数 `sections`（可省略）：`system` `cpu` `memory` `disk` `network` `connections` `listening`。

- **省略 = 概览**：`system`（主机名、系统、运行时长、电池）、`cpu`、`memory`、`disk`、`network`，
  再加上连接数和开放端口的**数量**（不含明细，保持结果很小，约 4–6 KB）。
- 要明细时点名：`connections`（已建立的连接：本地/远端地址、进程）、`listening`（开放端口）。

| 部分 | 内容 |
|---|---|
| `system` | 主机名、操作系统、架构、运行时长（小时）、电池电量与是否接电 |
| `cpu` | 型号、物理/逻辑核数、总使用率和每核使用率、当前/最高频率 |
| `memory` | 总量、已用、可用、使用率、交换空间 |
| `disk` | 每个盘：盘符、文件系统、总量、已用、剩余、使用率（读不了的盘只报错，不影响其它盘） |
| `network` | 网卡（启用的排前面）：名称、是否启用、速率、MAC、IP 地址；开机以来的收发流量 |
| `connections` | 连接总数、按状态分类、已建立连接的明细（最多 100 条，超出会标 `truncated`） |
| `listening` | 开放端口的数量，以及明细（最多 200 条）：协议、端口、绑定地址、进程、范围 |

### “对外开放”怎么判断

每个监听端口有 `scope`：

- `network`：**其它机器可以连上来**。绑定在 `0.0.0.0` / `::`（所有网卡），或绑定在某个非回环地址；
- `local`：只绑定在 `127.0.0.1` / `::1`，只有本机能访问。

注意：`network` 只说明**程序愿意接受**外部连接，不等于一定能从外面连到——还要看防火墙。
工具不检查防火墙规则，回答时请不要把它说成“已暴露在公网”。

同一个服务的 IPv4 和 IPv6 绑定（例如 `0.0.0.0:8080` 与 `:::8080`）合并为一条，`addresses` 列出
全部绑定地址。无法读取进程名时（系统进程需要管理员权限）`process` 是 `null`，不会编造。

### 出错时

每个部分各自读取，**一部分失败不影响其它部分**：该部分变成 `{"error": "..."}`。常见原因是权限
（例如列出其它用户的连接），以管理员运行应用可以看到更全的进程信息。

## 依赖与实现

- 使用应用已有的依赖 `psutil`，没有新增依赖，也不联网。
- `sysinfo/collect.py`：读取与整理，系统调用都经过 `Probe`，所以测试可以注入假数据；
- `sysinfo/__init__.py`：注册工具和两个按钮；
- `extension.json`：名称与按钮名都写成**多语言**（`label: {en, zh-CN, zh-TW}`）；
- 内置扩展：用户可以在设置里停用，不能卸载。
